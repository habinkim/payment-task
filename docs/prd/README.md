# PRD (작업 사이클 기록)

이 디렉터리는 **작업 사이클 단위**로 "무엇을 왜 만드는가"를 남긴다. 사이클 하나가 끝나면 해당 문서는 더 고치지 않고 완료 상태로 닫는다. 결정이 뒤집히면 문서를 지우지 않고 뒤집힌 사실과 계기를 그 문서에 남긴다.

문서 성격이 다른 것들과 구분한다.

| 문서 | 답하는 질문 | 생명주기 |
|---|---|---|
| **PRD** (이 디렉터리) | 이 사이클에서 무엇을 왜 만드는가 | 사이클마다 신규. 끝나면 동결 |
| [SPEC](../SPEC.md) | 무엇을 만드는가 (API, 스키마, 규칙) | 계속 추가되고 갱신됨 |
| [ADR](../adr/README.md) | 왜 이렇게 결정했는가 | 불변. 바뀌면 새 번호로 대체 |
| [requirement](../requirement/README.md) | 과제가 무엇을 요구했는가 | 원문 그대로. 수정 금지 |

## 사이클

| # | 제목 | 상태 | 범위 |
|---|---|---|---|
| [000](PRD-000-기반설계와스캐폴딩.md) | 기반 설계와 스캐폴딩 | **완료** | 도메인 조사, ADR 7건, 빌드 골격, V1 스키마 |
| [001](PRD-001-결제플로우.md) | 결제 처리 핵심 플로우 | **완료** | 도메인 객체, 결제 API, 멱등성, 동시성 |
| [002](PRD-002-조회와정합성.md) | 조회와 정합성 확인 | 예정 | 조회 API, `UNKNOWN` 확정, HTTP 계층 검증 |
| [003](PRD-003-지갑충전과마감.md) | 지갑 충전과 제출 마감 | 예정 | 충전 API, ArchUnit, README |

## 사이클을 나눈 기준

의존 순서를 따랐다. 앞 사이클 없이 뒤 사이클을 만들 수 없어야 한다.

- 001은 000의 설계 판단 위에서만 성립한다.
- 002의 정합성 확인은 001이 `UNKNOWN` 상태를 만들어야 대상이 생긴다.
- 003의 충전은 001, 002와 독립적이지만, 남은 요구를 마감과 함께 묶는 편이 효율적이다.

001에서 `UNKNOWN` 상태를 만들되 확정 수단은 002에서 만든다. 상태만 있고 확정할 수 없는 기간이 생기는데, 순서를 뒤집을 수는 없으므로 받아들인다.
