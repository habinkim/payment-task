# PRD-001. 결제 처리 핵심 플로우

| 항목 | 값 |
|---|---|
| 상태 | **예정** |
| 선행 | [PRD-000](PRD-000-기반설계와스캐폴딩.md) |
| 대응 스펙 | [SPEC](../SPEC.md) §3 도메인, §5.1 결제 요청, §6 처리 규칙, §9 게이트웨이 |

---

## 무엇을 왜 만드나

이 사이클은 과제의 본체다. 결제 요청 하나가 들어와 원장에 기록되고, 게이트웨이 승인을 거쳐, 지갑에서 금액이 빠지고, 결과가 확정되기까지를 만든다.

명세의 시스템 요구사항 1번(결제 이력)과 3번(외부 결제 API 연동), 그리고 2번의 차감 부분이 여기서 충족된다.

## 이 사이클이 풀어야 하는 문제

**돈이 두 곳에서 움직인다.** 외부 게이트웨이의 원장과 우리 지갑이다. 둘 사이에 원자성이 없어서, 한쪽만 성공하는 경우가 반드시 생긴다. 이 사이클의 난이도는 전부 여기에 있다.

구체적으로 세 가지를 막아야 한다.

| 위험 | 발생 조건 | 대응 |
|---|---|---|
| 미아 거래 | 외부 승인 후 잔액 부족 | 사전검증으로 원천 차단([ADR 0005](../adr/0005-pre-check-balance-before-external-call.md)) |
| 잔액 음수 | 동시 결제가 같은 지갑을 소진 | 조건부 UPDATE로 원자화([ADR 0003](../adr/0003-atomic-balance-deduction.md)) |
| 이중 차감 | 타임아웃 후 클라이언트 재시도 | `paymentNo` UNIQUE 제약([ADR 0002](../adr/0002-payment-no-as-idempotency-key.md)) |

## 범위

**포함**

- `Payment` 도메인 객체 — 상태 전이와 불변식
- `Wallet` 도메인 객체 — 잔액 판정과 차감
- 영속 계층 — 엔티티, 리포지토리, 캡슐
- `MockPaymentGatewayClient` — 시나리오 판정
- 결제 처리 서비스 — 트랜잭션 경계 분리
- `POST /api/v1/payments`
- 단위 테스트와 동시성 테스트

**제외**

| 항목 | 어디로 |
|---|---|
| 조회 API | PRD-002 |
| `UNKNOWN` 확정 절차 | PRD-002 |
| 지갑 충전 | PRD-003 |
| `HttpPaymentGatewayClient`와 WireMock 검증 | PRD-002 |

`UNKNOWN` **상태 자체는 이 사이클에서 만든다.** 타임아웃 시 그 상태로 기록까지 하되, 확정하는 절차는 다음 사이클이다. 상태만 있고 확정 수단이 없는 기간이 생기는데, 이는 의도된 것이다. 상태 없이 확정 절차를 먼저 만들 수는 없다.

## 완료 판정

측정 가능한 것으로만 적는다.

| # | 기준 | 검증 방법 |
|---|---|---|
| 1 | 정상 결제가 `COMPLETED`로 끝나고 잔액이 정확히 차감된다 | 통합 테스트 |
| 2 | 잔액 부족 시 게이트웨이를 **호출하지 않고** 실패한다 | Mock 호출 횟수 0 검증 |
| 3 | 게이트웨이 거절이 `PAYMENT_DECLINED`로 기록된다 | 통합 테스트 |
| 4 | 타임아웃이 `UNKNOWN`으로 남고 차감이 일어나지 않는다 | 통합 테스트 |
| 5 | 동시 결제 2건에서 잔액이 음수가 되지 않는다 | 동시성 테스트 |
| 6 | 동일 `paymentNo` 재요청이 재차감하지 않는다 | 동시성 테스트 |
| 7 | 외부 호출이 트랜잭션 밖에서 일어난다 | 코드와 ArchUnit |
| 8 | 종료 상태에서 재전이하면 예외가 난다 | 단위 테스트 |

기준 2가 이 사이클의 핵심이다. 사전검증이 실제로 외부 호출을 막는지를 **호출 횟수로** 증명한다.

## 열린 질문

| # | 질문 | 진행 방식 |
|---|---|---|
| 1 | 결제 응답에 지갑 잔액을 포함할 것인가 | 포함하는 쪽으로 진행. 차감 후 조회가 한 번 더 필요하지만 3rd party 입장에서 유용하다 |
| 2 | 승인 후 차감 실패 시 보상 취소를 호출할 것인가 | v1에서는 하지 않는다. 취소 API 명세가 과제에 없어 임의 정의가 되고, 검증할 수 없다. 대신 카운터로 집계한다 |
